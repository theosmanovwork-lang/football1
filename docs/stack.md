# Стек и архитектура

**Решение:** React + TypeScript + Electron (утверждается по итогам T001).
Полное сравнение с Unity и Tauri — документ «Unity против Tauri + React + TypeScript — сравнение стеков» (claude.ai).

## Почему этот стек

- Игра по сути является приложением без 3D. Лучшие инструменты для интерфейсов уровня Notion/Linear — веб-технологии.
- Разработку ведёт Claude Code. С этим стеком он работает полностью сам: пишет, запускает, тестирует и проверяет интерфейс по скриншотам.
- Для Steam у Electron есть готовая библиотека steamworks.js (достижения, облачные сохранения, Мастерская, оверлей). У Tauri такой готовой интеграции нет, вызовы Steam пришлось бы делать через Rust.
- У всех игроков одинаковый встроенный Chromium — нет различий отрисовки между Windows и macOS.
- Бесплатно; планшетный режим и будущая мобильная версия делаются той же вёрсткой.

Чем жертвуем: консолями и полноценным 3D-матчем. Ни то, ни другое не входит в планы.

## Компоненты

| Слой | Технология | Зачем |
| --- | --- | --- |
| Оболочка | Electron + electron-vite, electron-builder | Сборка под Windows и macOS, Steam |
| Интерфейс | React + TypeScript, Tailwind CSS, shadcn/ui | Интерфейс уровня Linear/Notion |
| Таблицы | TanStack Table + TanStack Virtual | Тысячи строк без подтормаживаний |
| Командная палитра | cmdk | Ctrl+K |
| Графики | Recharts | Живые метрики, отчёты |
| Состояние интерфейса | Zustand | Простое и предсказуемое |
| Ядро симуляции | TypeScript в Web Worker + Comlink | Не блокирует интерфейс, тестируется отдельно |
| Данные | SQLite (better-sqlite3 в main-процессе) | Сохранения, редактор, моды |
| Steam | steamworks.js в main-процессе | Достижения, облако, Мастерская |
| Тесты | Vitest, Playwright | Автоматическая проверка ядра и интерфейса |

## Процессы и потоки данных

```
 React-интерфейс (renderer) ──Comlink──► Web Worker: packages/sim (ядро)
          │
          │ window.api (contextBridge, типизированный)
          ▼
 preload ──IPC──► main-процесс: окна, SQLite, Steam, файлы модов
```

- Интерфейс вызывает ядро через Comlink и получает сериализуемые снимки состояния.
- Доступ к диску, базе и Steam — только через main-процесс по IPC.
- Типы контрактов IPC и API ядра лежат в `packages/shared`.

## Важная деталь про steamworks.js

В README steamworks.js для использования в renderer предлагается включить `nodeIntegration` и выключить `contextIsolation`. Мы так **не делаем**: это ослабляет безопасность. steamworks.js инициализируется в main-процессе, интерфейс получает данные через IPC. Оверлей Steam включается вызовом `electronEnableSteamOverlay()` в конце main-скрипта; его работу проверяем отдельно в T001.
