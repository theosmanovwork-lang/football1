# Журнал решений

Каждое важное решение записывается сюда: дата, решение, причина, что отвергли. Новые записи — сверху.

## ADR-013 — Совместная работа через репозиторий

- **Дата:** 2026-10-25
- **Решение:** документацию (`docs/`, `CLAUDE.md`, `PROMPTS.md`, `SETUP.md`, `README.md`) обновляет Claude в чате проекта на claude.ai и сам делает коммиты в этот репозиторий. Код пишет Claude Code. В начале каждой сессии Claude Code делает `git pull`.
- **Причина:** итераций будет много; архив с набором файлов пришлось бы каждый раз распаковывать и переносить вручную, рискуя затереть работу Claude Code.
- **Правило конфликтов:** если оба поменяли один файл — Claude Code не перезаписывает чужие правки, а объединяет и сообщает пользователю.

## ADR-012 — Дизайн: тёмный интерфейс в духе Linear, адаптивное окно

- **Дата:** 2026-10-25
- **Решение:** утопленная панель контента на тёмной подложке, группы-списки, вкладки-«таблетки», иконки Lucide, анимации 120–200 мс через Motion; при сужении окна интерфейс перестраивается (1440 / 1200 / 1024 px), а не масштабируется.
- **Причина:** профессиональный рабочий инструмент; урок FM26 — интерфейс под касания неудобен за компьютером.
- **Эталон:** макет главной v2 в Claude Design. Дополняет ADR-006: экраны переносятся только по макетам.

## ADR-011 — Симбиоз реальных клубных инструментов

- **Дата:** 2026-10-25
- **Решение:** игра объединяет функции реальных систем (Hudl, StatsBomb, Opta, IMPECT, SkillCorner, Wyscout, Catapult, Kitman Labs, Iterpro, Coach Paint) в одном приложении. Воссоздаются функции и процессы, а не интерфейсы, названия и логотипы; в игре у всех вымышленные названия.
- **Причина:** реализм — главное отличие игры; один интерфейс вместо разрозненных систем — то, к чему стремятся реальные клубы.
- **Подробности:** документ «Реальные клубные инструменты — что воссоздавать в игре» и `docs/concept.md`, раздел 4.

## ADR-010 — Планшет: тактическая карта и 2D-повторы без постоянного 2D-просмотра

- **Дата:** 2026-10-25
- **Решение:** в день матча на планшете — тактическая карта (позиции сверху с наложениями) и 2D-повторы эпизодов от аналитика; режима «смотреть весь матч в 2D» нет.
- **Причина:** в реальности вид сверху — аналитический экран (Spiideo, SciSports, карта контроля поля на скамейке «Ливерпуля»), а не трансляция; так сохраняется ощущение рабочего инструмента.
- **Отвергли:** постоянный 2D-просмотр матча как в FM.

## ADR-009 — Все модули в MVP

- **Дата:** 2026-10-25
- **Решение:** все модули входят в MVP в базовой глубине, порядок сборки — `docs/concept.md`, раздел 12.
- **Риск:** срок первой играбельной версии сильно растёт; держим глубину модулей базовой и собираем по зависимостям.

## ADR-008 — Собственный центр данных

- **Дата:** 2026-10-25
- **Решение:** все события и метрики (xG, PPDA, xT, Pitch Control, обойдённые соперники и др.) считаются из нашего движка с начала сохранения. Внешние наборы данных (в том числе открытые данные StatsBomb) не используются.
- **Причина:** независимость от лицензий; честные метрики из симуляции.
- **Открыто:** зависит ли доступ к данным от бюджета клуба — см. концепцию, раздел 13.

## ADR-007 — Гибридный пространственный движок матча

- **Дата:** 2026-10-25
- **Решение:** пространственный 2D-движок (координаты всех 22 игроков и мяча во времени) для матчей игрока и важных матчей; быстрый статистический режим для фоновых матчей, откалиброванный по пространственному. Оба в `packages/sim`, единый формат результата.
- **Причина:** 2D-повторы, тактическая карта, xT, Pitch Control, конструктор стандартов и честное влияние тактики невозможны без координат.
- **Следствие:** статистическая модель в T001 — только временная заглушка для проверки скорости стека.

## ADR-006 — Экраны по макетам из Claude Design

- **Дата:** 2026-10-25
- **Решение:** пользователь сам рисует экраны в Claude Design и передаёт готовые макеты; Claude Code переносит их в код. Библиотеки интерфейса поставлены заранее, экраны без макета не делаются.
- **Поставлено:** Tailwind CSS 4, основа shadcn/ui (`components.json`, `cn()`, токены темы и плотности в `styles.css`), radix-ui, lucide-react, cmdk, Zustand, TanStack Table 9 и Virtual, Recharts, Comlink. Всё вшивается в сборку интерфейса, поэтому лежит в `devDependencies`.
- **Отложено:** steamworks.js (T001, шаг 5) и better-sqlite3 (T002) — нативные модули, их надо пересобирать под Electron; ставим вместе с кодом, который их использует.
- **Влияние на T001:** шаг 2 (боковое меню, палитра, темы) делается по макету, когда он будет. Шаги 3 (ядро) и 5 (Steam) от макетов не зависят.

## ADR-005 — Версии инструментов каркаса

- **Дата:** 2026-10-25
- **Решение:** TypeScript 6.0 (не 7.0), Vitest 5, замеры `npm run bench` — обычные тесты Vitest с ручным таймером (`packages/sim/bench/`), конфиги Vite в формате `.mts`, workspace-пакеты (`@fm/shared`, `@fm/sim`) отдаются исходниками TypeScript и всегда вшиваются в сборку.
- **Причина:** typescript-eslint пока поддерживает TypeScript только до 6.0. В Vitest 5 API `bench` экспериментальный и переделан, а Vitest 4 не ставится текущей версией npm (ошибка `edgesOut`); ручной таймер даёт ровно то, что нужно по T001 — среднее из 5 запусков. Изолированный preload (`sandbox: true`) может загружать только `electron`, поэтому общий код вшивается в бандл.
- **Отвергли:** TypeScript 7 (ломает линтер), Vitest 4 (не устанавливается).

## ADR-004 — Electron 43 вместо последней версии

- **Дата:** 2026-10-25
- **Решение:** закрепить Electron 43.8.3.
- **Причина:** у пользователя macOS 12.7.6. Начиная с Electron 44 нужна macOS 13 или новее (Chromium прекратил поддержку macOS 12). На Electron 43 приложение можно запускать и проверять на этом компьютере.
- **Чем платим:** Electron поддерживает три последние версии; 43 выйдет из поддержки с выходом Electron 46 (примерно через 2–3 месяца). До раннего доступа обновимся на актуальную версию — для игроков в Steam это значит минимум macOS 13, что приемлемо.
- **Отвергли:** Electron 45 (не запускается на macOS 12).

## ADR-003 — Вымышленный мир по умолчанию

- **Дата:** 2026-10-25
- **Решение:** игра выходит с вымышленными лигами, клубами и игроками. Реальные данные — только моды сообщества.
- **Причина:** права на имена игроков в видеоиграх продаются через профсоюзы, клубы и лиги; распространять реальную базу самим рискованно для коммерческого релиза.
- **Отвергли:** официальный пак с реальными игроками от разработчика.

## ADR-002 — Ядро симуляции отдельно от интерфейса

- **Дата:** 2026-10-25
- **Решение:** ядро — чистый TypeScript в `packages/sim`, работает в Web Worker, детерминировано через генератор с зерном.
- **Причина:** тестируемость, воспроизводимость сезонов, интерфейс не зависает, ядро можно позже запустить на сервере для онлайн-режима.

## ADR-001 — Стек React + TypeScript + Electron

- **Дата:** 2026-10-25
- **Решение:** React + TypeScript для интерфейса, Electron как оболочка. Утверждается по итогам T001.
- **Причина:** интерфейсный продукт без 3D; лучшая работа с Claude Code; готовая интеграция со Steam через steamworks.js.
- **Отвергли:** Unity 6 + UI Toolkit (мало UI-компонентов, ручные шаги в редакторе); Tauri (нет готовой интеграции Steam, разные движки отрисовки на разных ОС).
