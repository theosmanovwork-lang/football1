# T001 — Отчёт

## Шаг 1. Каркас репозитория — выполнен

Дата: 2026-10-25. Проверялось в облачной сессии Claude Code (Linux x64, Node 22.22).

### Что сделано

- npm workspaces: `apps/desktop` (Electron + electron-vite + React), `packages/sim` (ядро), `packages/shared` (общие типы и контракт моста).
- TypeScript strict во всех пакетах (плюс `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`).
- ESLint (с правилами изоляции и детерминизма ядра), Prettier, Vitest, Playwright.
- Команды: `dev`, `dev:web`, `typecheck`, `lint`, `format`, `test`, `test:e2e`, `bench`, `build`.
- Окно Electron: `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`. Ссылки открываются во внешнем браузере. Content-Security-Policy в `index.html`.
- Типизированный мост `window.api` (`AppApi` в `packages/shared`): пока один метод `getAppInfo` через IPC. Мок моста для браузера — `apps/desktop/src/renderer/src/bridge.ts`.
- Экран-заглушка: название, среда (Electron или браузер), платформа, версия ядра.

### Как проверить самому (на Mac)

Нужны Git и Node.js 22 LTS.

```
git clone https://github.com/theosmanovwork-lang/football1.git
cd football1
npm install
npm run dev
```

Должно открыться окно «Футбольный менеджер» со строкой «Среда: Приложение Electron». Закрыть — Cmd+Q.

```
npm run dev:web
```

Откройте в браузере http://localhost:5173 — та же заглушка, но «Среда: Браузер (мок моста)». Остановить — Ctrl+C в терминале.

### Проблемы и решения

- **macOS 12 у пользователя.** Electron 44+ требует macOS 13, поэтому закреплён Electron 43 (ADR-004).
- **TypeScript 7** не поддерживается линтером — взят 6.0 (ADR-005).
- **Vitest:** `bench` в Vitest 5 экспериментальный, Vitest 4 не устанавливается — замеры сделаны через обычные тесты с таймером (ADR-005).
- **Electron не скачивался при `npm install`** на чистой машине («Electron uninstall»): новые версии Electron больше не качают бинарник сами. Добавлен `postinstall: install-electron` в корневой `package.json`.
- Сборка `.dmg` под macOS проверяется только на Mac (`npm run build`); в облаке проверена сборка под Linux.

## Шаг 2. Каркас приложения по макету главной — выполнен

Дата: 2026-10-25. Эталон — `docs/design/home-*.png` и исходник `docs/design/source/home/Desk.dc.html`.

### Что сделано

- **Окно (доделка шага 1 по ADR-014):** минимум 720 × 480; запоминаются размер, положение, развёрнутость и полноэкранный режим (`window-state.json` в папке данных приложения); если монитор отключён — окно открывается на основном; `backgroundThrottling: false`; фон окна в цвет темы (меняется вместе с темой через мост); масштаб интерфейса 90/100/110/125% через `setZoomFactor`.
- **Токены дизайна** (`styles.css`): тёмная тема — цвета из исходника макета один в один; светлая — те же роли, подобраны по контрасту (в макете её нет). Плотность: компактная (как в макете) и комфортная. Шрифты Inter и JetBrains Mono вшиты в приложение.
- **Раскладка** (`layout/layout.ts`, чистые функции + 11 тестов): точки 1440 / 1200 / 1024 / 860, правило «контент не уже 560 px», правая панель встроенная или выезжающая, меню полное, иконками или выезжающее. При переходе через точку — значения по умолчанию для зоны; внутри зоны ручные переключения сохраняются.
- **Перетаскивание границ** меню и правой панели: мышью, стрелками (Shift — шаг 48 px), Home или двойной щелчок — по умолчанию. Ширины запоминаются (ширина панели — отдельно для зон 1440 и 1200).
- **Каркас:** боковое меню (разделы и счётчики из макета), верхняя панель, нижняя строка, выезжающие меню и панель с затемнением (анимации Motion 180 мс).
- **Главная** по макету: показатели дня, «Требует решения», «Инсайты недели», «План недели» (вкладка «Неделя»), «Нагрузка × готовность», «Доступность», правая панель «Следующий матч». Данные — вымышленные заглушки из макета в `screens/home/homeData.ts`; на шаге 3 их начнёт давать ядро.
- **Остальные разделы меню** — пустые страницы с названием (макетов пока нет). «Состав» — будущий раздел «Игроки» из T001.
- **Настройки** (тема, плотность, масштаб) — простой список; открываются из палитры или Ctrl/Cmd+, — места для них в макете нет.
- **Командная палитра** Ctrl/Cmd+K (cmdk): переход в любой раздел, тема, плотность, меню, панель.
- **Горячие клавиши:** `[` — меню, `]` — правая панель, Ctrl/Cmd+, — настройки.
- Настройки интерфейса пока хранятся в `localStorage` с номером версии схемы; перенос в профиль пользователя — задача «Раскладки и кастомизация» (ADR-014).

### Сверка с макетом

Ширины и раскладка совпадают с подписями в макете: «окно 1440 px · контент 888 px», «1200 · 684», «1024 · 956», «800 · 792»; карточки «Нагрузка × готовность» и «Доступность» стоят рядом на 1440 и 1024 и друг под другом на 1200 и 800 — как в макете.

Отличия:

1. **Значки статуса в строках** — контурные иконки Lucide, а в макете залитые кружки, нарисованные вручную. Так требует правило `CLAUDE.md` «иконки только Lucide, без заливки». Если нужны залитые — надо поменять правило.
2. **Иконки меню** — ближайшие из Lucide; «Тактика», «Матчевый день» и значок аналитика в правой панели выглядят немного иначе.
3. **Показатели дня на узком окне:** в макете при переносе четвёртой карточки на вторую строку остаётся пустое серое место; у нас карточка растягивается на всю строку.
4. **Светлой темы в макете нет** — сделана по тем же ролям цветов; стоит нарисовать эталон.
5. **Выбор клуба, «?», «Настроить виджеты», колокольчик, «Продолжить»** пока ничего не делают — их поведение в макете не описано или зависит от ядра (шаг 3).
6. **Окно 720 px при масштабе 110%** даёт логическую ширину 655 px — раскладка «меню скрыто» работает, контент 647 px.
