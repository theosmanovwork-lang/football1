# T001 — Прототип и проверка стека

**Цель:** за одну неделю проверить, что стек React + TypeScript + Electron выдерживает три главных риска проекта: скорость симуляции, большие таблицы и интеграцию со Steam. По итогам стек утверждается или пересматривается.

**Статус:** в работе — шаг 1 выполнен; для шага 2 библиотеки поставлены, экраны ждут макетов из Claude Design (ADR-006)
**Зависимости:** нет

## Что не входит в задачу

- Настоящий движок матча, тактика, трансферы, сохранения в SQLite. Это следующие задачи.
- Финальный дизайн. Нужен аккуратный каркас в духе Linear, но без полировки.

## Шаги

Делай шаги по порядку. После каждого шага остановись, покажи пользователю результат и как его проверить, сделай коммит.

### Шаг 1. Каркас репозитория

- npm workspaces: `apps/desktop`, `packages/sim`, `packages/shared`.
- `apps/desktop` создать через electron-vite с шаблоном React + TypeScript.
- TypeScript strict во всех пакетах, ESLint, Prettier, Vitest, Playwright.
- Скрипты из `CLAUDE.md`: `dev`, `dev:web`, `typecheck`, `lint`, `test`, `test:e2e`, `bench`, `build`.
- Безопасные настройки окна Electron: `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`.
- Минимальный размер окна 720 × 480; размер, положение, развёрнутость и монитор запоминаются между запусками.
- `backgroundThrottling: false` и `backgroundColor` окна в цвет темы (см. `CLAUDE.md`, «Окно и адаптивность»).
- Типизированный мост в preload и его мок для `dev:web`.

**Готово, когда:** `npm run dev` открывает окно с надписью-заглушкой, `npm run dev:web` открывает то же в браузере, все проверки проходят.

### Шаг 2. Каркас приложения

- Боковое меню в стиле Linear с тремя разделами-заглушками: «Входящие», «Игроки», «Настройки».
- Командная палитра Ctrl+K / Cmd+K (cmdk): переход между разделами, переключение темы.
- Светлая и тёмная тема, компактная и комфортная плотность — через CSS-переменные; выбор сохраняется.
- Tailwind CSS и shadcn/ui, иконки Lucide.
- Адаптивность по правилам раздела «Окно и адаптивность» в `CLAUDE.md`: правая панель-заглушка сворачивается кнопкой, меню сворачивается до иконок и прячется совсем, раскладка перестраивается на 1440, 1200, 1024 и 860 px; область контента не уже 560 px.
- Ширина меню и правой панели меняется перетаскиванием границы и запоминается.

**Готово, когда:** через Playwright MCP сделаны скриншоты всех трёх разделов в обеих темах и в четырёх ширинах окна (1440, 1200, 1024, 800); палитра открывается с клавиатуры; при сужении окна текст и иконки не уменьшаются; после сворачивания и разворачивания окна прогон сезона не прерывается.

### Шаг 3. Ядро: генерация мира и прогон сезона

В `packages/sim`:

- Генератор случайных чисел с зерном (`rng.ts`), без `Math.random`.
- Генератор вымышленного мира: 5 лиг × 20 клубов, по 25–30 игроков в клубе, плюс свободные агенты, всего около 5 000 игроков. Вымышленные имена из локальных списков, атрибуты 1–20, возраст, позиции, национальность.
- Упрощённая модель матча-заглушка: сила атаки и защиты из атрибутов игроков, голы по распределению Пуассона. В коде пометить, что это временная модель: настоящий движок будет пространственным и гибридным (ADR-007), заглушка нужна только для проверки скорости стека и позже станет основой быстрого режима для фоновых матчей.
- Календарь двухкругового турнира (38 туров на лигу) и турнирная таблица.
- Прогон полного сезона всех пяти лиг в Web Worker через Comlink.

Тесты (Vitest):

- одинаковое зерно даёт одинаковые таблицы всех лиг;
- разное зерно даёт разные таблицы;
- в каждой лиге каждый клуб сыграл 38 матчей, сумма очков сходится.

Бенчмарк `npm run bench`: время генерации мира и время прогона сезона, среднее из 5 запусков.

**Цель по скорости:** прогон сезона пяти лиг быстрее 5 секунд на ноутбуке среднего уровня. Если не укладываемся — записать замеры и варианты ускорения в отчёт, не оптимизировать преждевременно.

### Шаг 4. Таблица игроков на 5 000 строк

В разделе «Игроки»:

- Таблица всех игроков мира: имя, возраст, позиция, клуб, лига, национальность, общая оценка досье словом (по шкале из `docs/concept.md`).
- Сортировка по любой колонке, фильтр по позиции и лиге, поиск по имени.
- Виртуализация строк (TanStack Virtual).
- Кнопка «Сыграть сезон» запускает прогон в воркере, интерфейс при этом не зависает; после прогона доступна турнирная таблица выбранной лиги.

Замеры (Playwright): время сортировки и фильтрации на 5 000 строк, плавность прокрутки.

**Цель:** сортировка и фильтр быстрее 150 мс, прокрутка без видимых подтормаживаний, интерфейс отзывчив во время прогона сезона.

### Шаг 5. Проверка Steam

- Подключить steamworks.js **только в main-процессе**, за флагом окружения `STEAM_ENABLED=1`.
- Тестовый App ID 480 (Spacewar, тестовое приложение Valve).
- Через IPC отдавать в интерфейс статус: Steam запущен или нет, имя игрока.
- В «Настройках» показать статус Steam.
- Если Steam не запущен — приложение работает как обычно и пишет понятное сообщение в лог.

Эту проверку пользователь делает сам: на его компьютере должен быть установлен и запущен клиент Steam. Подготовь для него короткую инструкцию в отчёте: какую команду запустить и что он должен увидеть.

**Готово, когда:** с запущенным Steam в «Настройках» видно имя игрока; без Steam приложение не падает.

## Критерий успеха задачи

Все три проверки пройдены (скорость ядра, таблица, Steam) или по каждой непройденной есть понятный план. Пользователь получил отчёт и принял решение по стеку.
